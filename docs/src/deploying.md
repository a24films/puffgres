# Deploying

Our setup keeps related files — the things generated by `puffgres init` and modified by commands — in a `/apps/puffgres` folder. 

The puffgres service's Docker image, that runs based on the code in *this* repo, depends on this structure. It will manage its own state on your Postgres database. 

puffgres configs should live in your repo, in a `puffgres/` folder. The puffgres service image runs based on this directory structure of configs and transforms. puffgres' own state — applied configs, replication checkpoints, backfill cursors, the DLQ — lives in a dedicated Postgres schema (default `puffgres`) inside your source database. Nothing persists on local disk, so the container is stateless.

## CI

We run `puffgres check` to make sure schemas are up to date. You need to do this; if you don't and add a column, `puffgres` will accidentally embed / upsert the wrong columns. This will run automatically, too. 

## Observability

We support OpenTelemetry for tracing and metrics, and we've had good luck using Sentry. You just need to set `OTEL_EXPORTER_OTLP_ENDPOINT` and `OTEL_EXPORTER_OTLP_HEADERS` to use this, see the [Configuration](./configuration.md#environment-variables) section for example values.
